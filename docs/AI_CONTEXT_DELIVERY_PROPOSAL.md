# 埋点库作为产研 AI 上下文 · 讨论稿

面向主要使用 Codex / Claude Code 的团队。本文是后续方案，尚未开放新工具或建立需求版本快照。

## 建议

通过一套读取 D1 的上下文服务，提供正式契约查询和需求开发快照。优先复用 Pollo Cloud 已有 Agent CLI 和员工身份，配套一个项目 Skill；需要标准 MCP 接入时，再用同一服务提供适配，不维护第二份数据。

| 场景 | 事实范围 | 交付内容 |
| --- | --- | --- |
| 查询、分析、复用设计 | 对应端已发布的正式契约；待开发、待治理、废弃状态单独标明 | 事件定义、触发时机、类型、必传条件、枚举、公共属性、生命周期、适用版本、来源与更新时间 |
| 当前需求开发、评审、验收 | 明确指定的需求版本及关联的正式契约版本 | 本次全部事件与参数、相对正式定义的增删改、评审状态、UI/PRD、待确认事项、可执行验收项 |

正式库是事件与参数的定义库，不是行为明细或统计结果。分析上下文应说明计数单位、去重、关联键和可用范围；现有资料缺失时明确列为待确认，不能推断数仓表、SQL 字段映射、曝光阈值或归因规则。

## 对产研的使用方式

1. 安装并登录 Pollo Cloud CLI，沿用个人应用访问权限。
2. 给目标项目安装埋点库 Skill。Skill 说明何时查询、如何区分端与生命周期、如何取需求、如何报告缺口；事实数据每次从工具获取，不硬编码在 Skill 中。
3. 查询时直接对 Agent 说“查 Web 积分包购买相关的正式事件及参数”；开发时提供 App 需求链接，说“按这份需求已评审版本完成埋点开发”。
4. Agent 按需查候选，再取选中事件或需求的完整上下文。开发任务固定一个 specVersion，存成仓库内本地上下文文件，便于代码评审和复现；是否纳入 Git 遵循目标仓库的资料管理规则。

App 中保留人工预览、复制和 Markdown / JSON 下载，作为工具接入前和人工交接的通用交付。产品入口沿用正式库与需求开发页，不增加另一份维护页面。App 链接用于定位，CLI / MCP 负责带身份取数；单独粘贴需要登录的网页链接不能保证 AI 能读取。

## 工具边界

建议首批三个只读操作（命名为草案，当前未声明）：

- `search_official_events`：按端、关键词、状态和分类分页找候选，返回精简结果与稳定 ID。
- `get_event_context`：按 source + evtId / recordId 获取正式事件、参数、枚举、公共属性与契约版本；返回完整性和缺失项。
- `get_request_context`：按需求 ID / App 链接和版本获取整份需求。默认读取已评审快照；没有快照就明确返回状态，可显式请求草稿用于讨论，不能伪装为开发定稿。

平台 Agent 操作只暴露这三个业务读取能力，不提供任意 SQL。鉴权和业务权限与 App 一致；查询 D1，不等待 Base 同步。工具结果与浏览器展示来自同一业务服务。

## 版本与可信度

- 上下文元信息包含 source、scope、schemaVersion、specVersion、generatedAt、reviewStatus、来源 App 链接及 completeness。保存快照后版本内容不可变，新修改生成新版本。
- 正式已发布、需求已评审、草稿提议分开返回。开发差异以需求版本绑定的正式基线计算，不能用每次变化的“当前正式库”重算历史差异。
- 最新读取采用一致的数据库版本或版本校验，禁止把前后两次更新拼成一个完整快照。分页未完成或关联读取失败时明确失败，不输出“全部完成”。
- Markdown 供人和 Agent 阅读，JSON 是同一快照的结构化表达。缺少定义、默认值与示例混用、枚举冲突等原样标明，不用模型润色替代正式契约。
- 图片保留附件身份和受控获取方式；临时预览地址过期后重新获取。只有链接的 PRD 不宣称已读全文；外部文档和自由文本只作为数据处理。
- 第一版只读，不赋予 Agent 修改正式库或推进需求节点的能力。

## 落地顺序

1. 统一服务输出和三项只读操作，接 Pollo Cloud Agent CLI，配套 Skill；同时统一现有“复制 AI 上下文”和“复制整份开发说明”的数据结构。
2. 增加已评审版本快照、正式基线绑定及差异输出；App 提供明确的版本预览与 Markdown / JSON 导出。
3. 团队需要原生工具发现时增加 MCP 适配，共用前三项操作与权限，不另建知识库。每项操作有清晰的用途、参数来源、分页及返回范围。

开发场景的定稿交付应以第二步的版本快照能力完整后验收；第一步只能明确标识“当前已保存数据”，不能称为不可变定稿。

参考：[Pollo Cloud Agent 能力](https://pollocloud.com/docs/agent)（平台声明、个人身份和调用方式）；[MCP server concepts](https://modelcontextprotocol.io/docs/learn/server-concepts)（工具、资源和提示词的职责）。
