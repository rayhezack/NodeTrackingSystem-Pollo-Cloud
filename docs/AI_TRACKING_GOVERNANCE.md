# AI 埋点设计工作流与复用约束

## 实际调用链

专用 Skill 的唯一源文件是 `skills/pollo-tracking-design/SKILL.md`，其中包含业务规则、事件目录和规划/设计阶段协议。修改后运行 `npm run skill:tracking:prepare`，将原文打包到 `shared/tracking-skill.generated.ts`。构建前自动生成，测试及提交前校验源文件和产物一致。

`shared/pollo-tracking-policy.ts` 的 `loadTrackingDesignSkill(stage)` 在两个阶段加载同一个 Skill 文件，并附加当前阶段约束；Worker 与 NestJS 共用此装配器。模型请求的 system message 包含完整 Skill 文件内容及源文件哈希，user message 包含 PRD、正式库和当前阶段业务数据。正式规则不再手写在 TypeScript 提示词里。

1. 读取需求 PRD、附件、现有设计及当前端的完整正式事件、参数、公共属性和枚举表。
2. `generateReusePlan` 规划直接复用、扩枚举、补可选参数或新增事件，校验正式来源与生命周期。
3. `generateDesignBatches` 按事件生成设计；阶段提示词来自 `designPrompt`，校验失败最多修正一次。
4. `compileDesignResponse` 在结构解析与默认值填充前组装正式契约；模型只提供需求增量。随后由独立的 `enforceGovernance` 校验完整草稿，保存治理报告及正式库指纹。
5. 应用前重新读取正式库，验证版本与指纹，并使用重新治理后的结果写入设计工作台及设计参数表。

## 复用边界

- 正式事件的名称、定义、触发时机、适用端、处理方、公共属性、版本、最低版本和指标场景不得由模型覆盖；正式空值也不得臆测补齐。
- 正式参数的类型、必传规则、触发条件、定义、示例、适用端由编译器从快照继承（包括空值）；模型回传的不同内容只保留为待确认提议。遗漏继承字段是合法增量，不依赖模型修正或重试。正式参数未提供独立默认值，AI 提议的默认值不得自动生效。
- 枚举取值是正式值与新增值的并集，不能通过模型输出删除原值。复用事件新增参数只能为可选参数。
- 需求特有内容分别写入事件 `requestNotes` → 工作台“本次需求补充说明”，参数 `requestNotes` → 设计参数表“本次需求说明”。
- 模型改写元数据时，代码保留正式值，差异以“AI 提议、待确认、不改变正式口径”转入说明，不视为获批的实现要求。业务语义冲突仍需人工确认。
- 生成和应用都执行相同约束。`official-first-v3` 拒绝旧版草稿，要求重新生成；历史已经应用的设计不自动改写。

## 结构性防复发边界

| 层次 | 职责 | 验证 |
| --- | --- | --- |
| 正式库预检 | 同名有效参数的类型、必传条件、定义、枚举和状态有矛盾时，在规划前拒绝；不依赖行顺序 | 快照读取及编译器冲突回归 |
| Skill | 决定如何比较业务动作、复用事件、扩展枚举及补可选参数；复用字段使用增量协议 | 全文、阶段指令及源码 SHA-256 一致性测试 |
| 编译器 | 正式契约来自当前端快照；AI 仅提出增量；改写内容进入需求说明和待确认项 | Web/App、全部继承参数字段、空值、遗漏、输入不变与重复编译测试 |
| 校验器 | 对组装结果执行来源、生命周期、参数类型、必传规则及条件检查 | 独立篡改测试；新参数和废弃参数仍被拦截 |
| 应用 | 重读正式库，检查指纹并严格校验；不调用编译器修正已保存草稿 | 指纹漂移、旧版草稿及应用测试 |

新治理报告持久化 `skillSourceHash` 与 `designContractVersion=official-delta-v1`。它记录构建中实际嵌入的 Skill；修改源码后必须重新构建、部署，线上才会使用新版本。历史报告没有这两个可选字段，不能据此推断其 Skill 版本。

此边界消除了“模型复制正式字段不准确导致契约冲突”的生成失败路径。模型输出无效 JSON、正式库自身冲突、网络故障或业务语义不兼容仍可能失败或需要人工确认，不应自动放行。单元测试及模拟接口验证不能代替线上 PRD 的实际验收。

手动设计、参数编辑和保存是普通表单/API 流程，不逐次调用 Skill；两阶段 AI 初稿生成才会向模型注入 Skill 全文。程序校验约束模型输出，Skill 的自校验声明不等于已经通过业务审核。

## 开发交接

“复制整份需求开发说明”导出已保存的同需求全部事件和参数、各流程字段、参与人、设计素材引用、Base 链接、待确认项与实施检查表。Markdown 内含结构化 JSON。任何事件/参数读取失败都会停止复制，避免不完整上下文；剪贴板失败则提供完整文本手动复制。PRD 全文和图片二进制不内嵌。

## Base 字段

App 与 Web 设计工作台均增加文本字段“本次需求补充说明”；正式事件库与正式参数库不增加需求专属字段。
